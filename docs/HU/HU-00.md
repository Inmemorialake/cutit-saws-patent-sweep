| Campo | Valor |
|---|---|
| **Qué es** | Tarea técnica previa. No tiene criterios de aceptación del PB ni endpoints de negocio. |
| **Por qué existe** | HU-02, HU-04 y HU-01 comparten modelo de datos, seguridad, manejo de errores y configuración de clientes. Si cada HU crea "lo mínimo" por su cuenta, se duplica y se rehace. |

## 1. Qué se construye

### 1.1 Proyecto base
- [ ] Maven, Java 21, Spring Boot 3. Dependencias: web, validation, data-jpa, security, actuator, springdoc-openapi, resilience4j, caffeine, micrometer-tracing, micrometer-registry-prometheus, lombok, flyway, postgresql.
- [ ] Paquetes por capa: `controller`, `service`, `integration`, `repository`, `model`, `util` (P01).
- [ ] `application.yml` + `application-dev.yml`, `application-prod.yml`, `application-test.yml` (P21). **Secretos solo por variables de entorno** (`${DB_PASSWORD}`, `${JWT_SECRET}`).
- [ ] `docker-compose.yml` mínimo con `postgres:16` (la API, Prometheus y Grafana llegan después).
- [ ] Dependencias de test: JUnit 5, Mockito, `spring-security-test`, Testcontainers (PostgreSQL), WireMock, ArchUnit.

### 1.2 Modelo de datos (Flyway + entidades JPA + repositorios)
Referencia: **MER en `docs/img/fig-001.png`** y descripción en DAS §3 (`docs/DAS_Patent_Sweep_V3.0.md`, sección 3 Vista Física).

| Entidad | Campos clave | Lo usan |
|---|---|---|
| `Formula` | `codigo` (PK, `form-NNN`), `nombre`, `descripcion`, **`estadoVigilancia`** (estado precalculado de HU-04), `ultimoDictamen`, `fechaUltimaRevision` | 01, 02, 03, 04 |
| `Patente` | `patenteId` (`PAT-NNNNNN`), `titulo`, `resumen`, `reivindicaciones`, `tipoProducto`, `estadoPatente` (`CONCEDIDA`/`EN_TRAMITE`/`EXPIRADA`), `fechaSolicitud`, `fechaConcesion`, `fechaVencimiento`, `jurisdiccion` | 01, 02, 08 |
| `Conflicto` | `conflictoId` (6 dígitos), FK fórmula, FK patente, `estado` (`DETECTADO`/`DESCARTADO`), `fechaDeteccion`, `motivoDescarte`, `usuarioDescarte` · **UNIQUE `(formula, patente)`** | 01, 02, 04, 07, 09 |
| `EventoRevision` | FK fórmula, `tipoOrigen` (`BARRIDO_AUTOMATICO`/`BUSQUEDA_MANUAL`/`EVALUACION`), `resultado` (`CON_CONFLICTO`/`SIN_CONFLICTO`/`FALLO_TECNICO`), `usuarioResponsable`, `parametros`, `traceId`, `fecha` · **append-only** | 01, 02, 04, 05 |
| `Barrido` | `inicio`, `fin`, `estado` (`EN_CURSO`/`COMPLETADO`/`FALLIDO`), conteos (procesadas, conConflicto, sinConflicto, noProcesadas), `mensaje` | 01 |
| `Evaluacion` | `ticket`, FK fórmula, componentes, `dictamen` (`SIN_INFRACCION`/`INFRACCION`), `estado` (`EN_PROCESO`/`COMPLETADA`/`FALLIDA`/`PENDIENTE_DE_ENVIO`) | 03, **04** (lee `EN_PROCESO`/`PENDIENTE_DE_ENVIO`) |
| `Configuracion` | `frecuencia` (en horas), `fechaDesde`, `fechaHasta`, `clasificaciones` (IPC/CPC), `activa` · **solo una fila activa**, las demás son historial inmutable | 01, 02, 06, 10, 11 |
| `ClasificacionCatalogo` | código IPC/CPC válido | 02, 03, 10 |
| `Usuario` | `username`, `passwordHash`, `rol` (`ADMINISTRADOR`/`SERVICIO`) | login |

- [ ] Todos los enums de estado con sus **transiciones válidas** en un método (P17), p. ej. `Conflicto`: `DETECTADO ↔ DESCARTADO`.
- [ ] Restricciones repetidas en entidades: `@Column(nullable=false, length=…)` (P06).
- [ ] Repositorios de historial (`EventoRevision`, `Configuracion` inactivas): **solo `save`**, sin `delete` ni `update` (P18).
- [ ] **Datos iniciales** (migración o `data.sql` de dev): configuración activa con **frecuencia 1 día** y criterios iniciales precargados; catálogo IPC/CPC; usuarios `admin` (ADMINISTRADOR) y `fabricacion` (SERVICIO).
- [ ] Notificación (HU-12) **no** va aquí.

### 1.3 Transversal (Utility Layer)
- [ ] **`GlobalExceptionHandler`** (P07, P19): `ProblemDetail` con `title`, `detail`, `traceId`. Jerarquía base de excepciones de dominio (`FormulaNoEncontradaException`, `MaterialesNoDisponibleException`, etc., se agregan según cada HU).
- [ ] **`traceId`**: Micrometer Tracing → MDC → patrón de logs `%X{traceId}`.
- [x] **Seguridad** (P26, P27): `POST /api/v1/auth/login` autentica usuarios existentes y emite JWT; filtro que valida firma y vigencia; `SecurityFilterChain`; roles `ADMINISTRADOR` y `SERVICIO`; `@EnableMethodSecurity`. Utilidad para obtener el usuario del `SecurityContext`.
- [ ] **Resilience4j**: estructura de configuración en `application.yml` (retry 3×/5 s, timelimiter 20 s/30 s, circuit breaker). Cada HU añade sus instancias.
- [ ] **Caffeine** (`@EnableCaching`) para el catálogo IPC/CPC (P15).
- [ ] **springdoc** (P24): `/swagger-ui.html`, esquema de seguridad JWT, info del API.
- [ ] **Actuator** (P28, P23): `/actuator/health` con indicador de PostgreSQL y `/actuator/prometheus`.
- [ ] Config del `RestClient` base para clientes de Integration (sin métodos de negocio todavía).
