# HU-02 — Búsqueda manual de patentes en conflicto con una fórmula

| Campo | Valor |
|---|---|
| **Rol** | Ingeniero de Laboratorio (usuario autenticado vía GUI/Swagger) |
| **Prioridad / Puntos** | Must / 8 · Sprint 1 · **Se construye primera tras HU-00 (cimientos)** |
| **Historia** | Requiero realizar una búsqueda manual de patentes en conflicto con una fórmula puntual, para validar su viabilidad antes de su pase a fabricación. |
| **Idea clave** | Es el **primer flujo completo de detección**: consulta la fórmula, busca en la fuente de patentes, aplica la regla de coincidencia, registra conflictos y deja rastro en el historial. Aquí nacen `MotorCoincidencias` y `FuentePatentesPort`, que **HU-01 reutiliza**. |

## 2. Endpoint y Vista Web

### Vista Web (`static/`)
- **Navegación:** **Patentes > Búsqueda Manual** (habilitada para rol `ADMINISTRADOR`).
- **Formulario:** campo obligatorio `formulaId` con validación de formato `form-NNN` y botón **“Buscar Coincidencias”**.
- **Tabla de resultados:** renderiza `conflictoId`, `tituloPatente` (máx. 60 caracteres), `tipoProducto`, `estadoPatente` y `fechaConcesion`, incorporando enlaces provisionales (`#conflicto/{conflictoId}`) listos para conectar con **HU-08**.
- **Sin coincidencias:** muestra el mensaje literal `"No se detectaron conflictos relacionados con su búsqueda"`.

### `POST /api/v1/patentes/busqueda`

- **Consumidor:** usuario autenticado → `@PreAuthorize("hasRole('ADMINISTRADOR')")` *(único rol humano definido en el DAS; ver D-4)*.
- **Request:** `{ "formulaId": "form-001" }` — `@NotBlank`, `@Pattern("^form-\\d{3}$")`, `@Valid`.

**200 OK — con coincidencias**
```json
{
  "formulaId": "form-001",
  "conflictos": [
    { "conflictoId": "123456",
      "tituloPatente": "Aleación para cadenas de corte",
      "tipoProducto": "Cadena de corte",
      "estadoPatente": "CONCEDIDA",
      "fechaConcesion": "20/03/2024" }
  ],
  "mensaje": "Búsqueda completada correctamente"
}
```
**200 OK — sin coincidencias:** `conflictos: []` y `mensaje: "No se detectaron conflictos relacionados con su búsqueda"`.

- `conflictoId`: 6 dígitos. `tituloPatente`: **máx. 60 caracteres en esta tabla** (el título completo queda en BD para HU-08). `estadoPatente`: `CONCEDIDA | EN_TRAMITE | EXPIRADA`.

**Errores** (`ProblemDetail` con `title`, `detail`, `traceId`):

| Código | Cuándo | `detail` exacto |
|---|---|---|
| 400 | `formulaId` vacío o sin formato `form-NNN` | `El código de la fórmula es obligatorio y debe tener el formato form-NNN` |
| 404 | La fórmula no existe en Materiales | `La fórmula consultada no fue encontrada` |
| 409 | La fórmula está `DESCONTINUADA` | `No se puede buscar patentes para una fórmula DESCONTINUADA` |
| 503 | Materiales o la fuente no responden en 20 s tras 3 reintentos (5 s entre intentos) | `No fue posible realizar la consulta. Intente nuevamente` (registrar error con `traceId`) |
| 500 | Fallo interno de Patent Sweep | Mensaje genérico con `traceId` |
| 401/403 | Sin token / sin rol | Respuesta estándar de seguridad |

### Endpoints que consume
- `GET /formulas/{formulaId}` (Materiales/Fórmulas) → nombre, aplicación técnica, estado, componentes.
- Fuente externa de patentes, a través de `FuentePatentesPort`.

## 3. Flujo (orden de ejecución)

1. **Validar** request (`@Valid`) → 400.
2. `MaterialesClient.obtenerFormula(formulaId)` → 404 / 503. Si `estado == DESCONTINUADA` → 409.
3. `ConfiguracionService.criteriosVigentes()` → IPC/CPC y rango de fechas (si no hay, los iniciales precargados).
4. Armar la consulta: términos = **nombres de los materiales componentes + aplicación técnica**; filtros = IPC/CPC y rango de fechas.
5. `FuentePatentesPort.buscar(consulta)` con retry/timeout. Si falla tras reintentos → 503 y, **como la fórmula ya fue verificada**, registrar evento `FALLO_TECNICO`.
6. `MotorCoincidencias.evaluar(formula, patentes)` aplica la **regla de coincidencia** (abajo).
7. `ConflictoService.registrarNuevos(...)`: crea conflictos `DETECTADO` **sin duplicar** por pareja `formulaId + patenteId` (sin importar si el existente está `DETECTADO` o `DESCARTADO`, ni la versión de la fórmula).
8. `HistorialService.registrar(...)`: `tipoOrigen = BUSQUEDA_MANUAL`, `resultado = CON_CONFLICTO | SIN_CONFLICTO`, `usuarioResponsable` = **usuario del token** (`SecurityContextHolder`), `traceId`.
9. `EstadoFormulaService.recalcular(formulaId)` — conectado con HU-04.
10. Mapear a DTO, responder `200 OK` y renderizar en la vista **Patentes > Búsqueda Manual**.

**Si falla Materiales (paso 2) no se registra evento. Si falla la fuente (paso 5) sí, con `FALLO_TECNICO`.**

### Regla de coincidencia (compartida con HU-01, criterio 6)
Una patente es **conflicto potencial** si su **título, resumen o reivindicaciones** mencionan **al menos el 50 %** de los nombres de materiales de la fórmula, **con un mínimo de 2**.

`umbral = max(2, ceil(0.5 × nMateriales))` → 2→2, 3→2, 4→2, 5→3, 1→**nunca hay conflicto**.

Solo se compara por nombre de material (no por porcentajes). El resultado es un **candidato a revisión humana** (HU-08/09), no un dictamen legal.

Datos del conflicto (HU-01, 6.1): `conflictoId` (6 dígitos), `formulaId`, `fechaDeteccion`, `patenteId` (`PAT-NNNNNN`), `tituloPatente`, `tipoProducto`, `estadoPatente`, `fechaSolicitud`, `fechaConcesion`, `fechaVencimiento`, `jurisdiccion`, `resumen`, `reivindicaciones`.

## 8. Decisiones y discrepancias (anotadas en `docs/discrepancias.md`)
- **D-1 Ruta:** `POST /api/v1/patentes/busqueda` (PB y DAS coinciden salvo el prefijo `/api/v1`).
- **D-2 503 vs 500:** el DAS (S-07) dice 500 al agotar los 20 s; el PB V3.01 exige **503**. Se usa 503.
- **D-3 Normalización:** el PB no dice si se ignoran acentos/mayúsculas. Se normaliza (minúsculas, sin acentos) para evitar falsos negativos; confirmar con el PO.
- **D-4 Rol:** el PB dice "Ingeniero de Laboratorio" pero el DAS solo define `ADMINISTRADOR` y `SERVICIO`. Se usa `ADMINISTRADOR`.
- **D-5 Contenido de `conflictos`:** se devuelven **todos** los conflictos que coinciden en esta búsqueda (nuevos y ya existentes, con su `conflictoId`), no solo los nuevos.
- **D-6 Mensaje en body y GUI liviana:** los mensajes del PB se entregan tanto en el campo `mensaje` de la respuesta HTTP como renderizados en la vista `static/`.
